# 남은 과제와 결정 사항

우선순위는 "반응속도와 사용감"([monitoring-and-performance.md](monitoring-and-performance.md))을 기준으로 정했다.

## 반응속도 관련 (먼저)

- [x] 세션 정지/삭제 때의 프로세스 트리 종료를 백그라운드로 옮기기 (v0.5.5)
- [x] 화면 그리기 최적화: 인접한 같은 스타일 셀을 하나의 `Span`으로 묶기 (v0.5.5)
- [x] 터미널 커서 깜빡임/요동(Jitter & Flicker) 완전 제거: 터미널 포커스 시 200ms 강제 리드로우 억제, 단일 버퍼 동기화(Synchronized Update) 및 불필요한 `cursor::Hide` 제거
- [ ] 세션 시작(`Session::spawn`)에 걸리는 시간 측정.
- [ ] 직접 써 보며 입력 지연, 끊김을 확인(아직 사람이 체감을 확인하지 못함).
- [ ] 자동 업데이트의 확인창과 전체 흐름을 새 버전이 나온 상태에서 직접 확인(다음 릴리스 때).
- [ ] `Ctrl+Q`가 실제 Windows 터미널에서 포커스를 빠져나오게 하는지 확인(코드와 단위 테스트로만 검증).

## 기능

- [x] 이미 저장된 `\\?\` 접두사 경로 항목 정리. 로드할 때 `plain_path` 적용 (v0.5.5)
- [ ] 세션 종료 키를 마우스로도(가운데 버튼, 우클릭) 쓸 수 있게 하기. 종료 배너에 `s`로 치울 수 있다는 안내 추가.
- [ ] 마우스 이벤트를 세션으로 전달(vim 같은 앱용). 지금은 마우스 캡처 때문에 전달되지 않는다.
- [x] Shift+Enter 전달 (v0.5.6)
- [ ] `S`(전체 시작)를 Caps Lock 사고가 없는 키로 옮길지 결정(`A`나 `Ctrl+S` 후보).
- [ ] 비Windows에서 모니터링(지금은 `None`을 돌려주고 표시 없음).

## 결정 기록

| 결정 | 이유 |
|---|---|
| 새 크레이트 대신 `windows-sys`로 CPU/메모리 측정 | 이미 쓰는 의존성이라 바이너리가 커지지 않고, 프로세스 트리 코드를 재사용한다. 대신 unsafe 코드가 늘었다 |
| 측정은 UI 스레드가 아닌 전용 스레드 | `measure()`가 약 20ms 걸려 타이핑이 끊길 수 있음 |
| `x`, `n`, `p`는 문서에서 빼고 동작은 유지 | 기존 손버릇을 깨지 않으면서 새 키를 안내하기 위해 |
| 큰 리팩터링은 기능 배포와 분리 | diff가 커서 위험하고, 반응속도 요구사항과 직접 관련이 없다 |
| 버전 표시는 TUI 사이드바 제목에 이미 있어서 추가 안 함 | 사이드바가 숨겨지는 60칸 미만과 `list`/`add` 명령 출력에는 없다. 필요해지면 추가 |
