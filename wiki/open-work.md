# 남은 과제와 결정 사항

우선순위는 "반응속도와 사용감"([monitoring-and-performance.md](monitoring-and-performance.md))을 기준으로 정했다.

## 반응속도 관련 (먼저)

- [x] 세션 정지/삭제 때의 프로세스 트리 종료를 백그라운드로 옮기기 (v0.5.5)
- [x] 화면 그리기 최적화: 인접한 같은 스타일 셀을 하나의 `Span`으로 묶기 (v0.5.5)
- [x] 터미널 커서 깜빡임/요동(Jitter & Flicker) 완전 제거: 터미널 포커스 시 200ms 강제 리드로우 억제, 단일 버퍼 동기화(Synchronized Update) 및 불필요한 `cursor::Hide` 제거
- [ ] 세션 시작(`Session::spawn`)에 걸리는 시간 측정.
- [ ] 직접 써 보며 입력 지연, 끊김을 확인(아직 사람이 체감을 확인하지 못함).
- [ ] 자동 업데이트의 확인창과 전체 흐름을 새 버전이 나온 상태에서 직접 확인(다음 릴리스 때).
- [ ] `Ctrl+Q`가 실제 Windows 터미널에서 포커스를 빠져나오게 하는지 확인(코드와 단위 테스트로만 검증).

## 기능

- [x] 이미 저장된 `\\?\` 접두사 경로 항목 정리. 로드할 때 `plain_path` 적용 (v0.5.5)
- [ ] 세션 종료 키를 마우스로도(가운데 버튼, 우클릭) 쓸 수 있게 하기. 종료 배너에 `s`로 치울 수 있다는 안내 추가.
- [-] 마우스 이벤트를 세션으로 전달: 하지 않기로 결정(2026-11-09). 아래 결정 기록 참고.
- [x] Shift+Enter 전달 (v0.5.6)
- [ ] `S`(전체 시작)를 Caps Lock 사고가 없는 키로 옮길지 결정(`A`나 `Ctrl+S` 후보).
- [ ] 비Windows에서 모니터링(지금은 `None`을 돌려주고 표시 없음).

## 구조

- [x] `main.rs` 모듈화: 5,300줄 단일 파일을 `app`, `config`, `input`, `session`, `sys`, `ui`, `updater`, `tests`로 분리 완료. `main.rs`를 110줄 진입점으로 축소.
- [x] `SessionStatus` enum 도입(`Running`, `Exited(Option<u32>)`, `Error(String)`, `Stopped`) 및 상태 모델 타입화.
- [x] `Mode` enum 하나로 모드 통합: `focus`/`sending`/`filtering`/`adding`/`show_help` 5개 불리언을 `mode: Mode`로 교체. 확인 팝업(`confirm_*`)은 데이터를 들고 있어 별도 유지. `app::run()`은 `App` 구조체와 `draw_*`, `on_*`, `key_*` 메서드로 분할 완료.

## 결정 기록

| 결정 | 이유 |
|---|---|
| 새 크레이트 대신 `windows-sys`로 CPU/메모리 측정 | 이미 쓰는 의존성이라 바이너리가 커지지 않고, 프로세스 트리 코드를 재사용한다. 대신 unsafe 코드가 늘었다 |
| 측정은 UI 스레드가 아닌 전용 스레드 | `measure()`가 약 20ms 걸려 타이핑이 끊길 수 있음 |
| `x`, `n`, `p`는 문서에서 빼고 동작은 유지 | 기존 손버릇을 깨지 않으면서 새 키를 안내하기 위해 |
| 큰 리팩터링은 기능 배포와 분리 | diff가 커서 위험하고, 반응속도 요구사항과 직접 관련이 없다 |
| 버전 표시는 TUI 사이드바 제목에 이미 있어서 추가 안 함 | 사이드바가 숨겨지는 60칸 미만과 `list`/`add` 명령 출력에는 없다. 필요해지면 추가 |
| 터미널 마우스 전달은 만들지 않음 | 얻는 것(vim, lazygit 같은 마우스 앱)보다 잃는 것이 큼: 마우스 모드 앱에서 `Shift` 없는 드래그 복사 상실, 비정상 종료 시 마우스 모드가 남아 복사가 안 되는 사고, 클릭(포커스)·가운데 버튼(매니저 복귀)·휠과의 규칙 충돌, 입력 경로 회귀 위험. 휠은 이미 전체 화면 앱에서 PageUp/PageDown으로 전달됨. 에이전트 위주 사용이라 필요가 낮음 |

## UI/UX 후보 (2026-11-09 정리)

- [x] 알림음을 줄임: 벨은 입력 대기(`?`)에서만, 10초에 한 번. 작업 완료는 소리 없이 창 제목의 `(N)` 카운트(대기 중 + 아직 열어 보지 않은 완료)로 알림. Windows Terminal `bellStyle`을 `["window","taskbar"]`로 하면 벨이 깜빡임으로 바뀜(README에 안내).
- [x] 업데이트 재시작 때 실행 중이던 세션을 모두 다시 시작(`squad resume <이름...>`, 내부용). 선택은 기존 `save_last_project`가 기억.
- [x] 히스토리 보기 `h`: 선택한 프로젝트의 `.squad/log/` SITREP 목록과 본문을 팝업으로 읽음.
- [x] 종료 배너 안내: 이미 `Enter/r restart · Esc dismiss`가 있어서 할 일 없음(위 항목은 낡은 메모였음).
- [x] 프로젝트 편집 `e`: 추가 폼을 재사용하되 명령과 autostart만 수정(경로·종류·이름은 고정, 보고 대상은 `u`). 저장은 `persist_edit`(디스크를 다시 읽고 반영). 실행 중인 세션은 재시작해야 새 명령을 씀.
- [x] 프로젝트 고정 `f`: `pinned = true`인 프로젝트가 자기 그룹(에이전트/서비스) 맨 위에 오고 이름 뒤에 `*` 표시. 지휘관 트리는 유지(고정은 최상위 지휘관 기준). 활동순 정렬은 안 함: 출력이 날 때마다 행이 움직여 선택이 흔들리기 때문.
- 안 함: `S` 키 변경. 전체 시작은 이미 확인창(`y`)이 있어 Caps Lock 사고가 실행으로 이어지지 않음.
- [x] 작업 이력 자동 기록: 에이전트 협조와 무관하게 squad가 작업 하나가 끝날 때마다(완료, 입력 대기, 작업 중 세션 종료) 프로젝트의 `.squad/log/<시각>-auto.md`에 항목을 씀(종료 시각·소요 시간·git 변경 파일·커밋·화면 마지막 줄). 에이전트 프로젝트는 `.squad/`가 없으면 등록·시작·세션 시작 때 자동 생성(`ledger::ensure_agent`; 기존 폴더는 건드리지 않음, 서비스는 제외). 훅과 SITREP은 보너스로 유지. 실제 `squad`를 pty에서 돌리는 e2e 테스트: `cargo test --test history_e2e -- --ignored --nocapture`.
