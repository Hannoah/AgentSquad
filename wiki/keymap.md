# 단축키

v0.5.2에 키맵을 lazydocker, vim 관례에 맞춰 다시 짰다. 상태줄 힌트, `?` 도움말, `squad --help`, README 표가 모두 같은 키를 가리켜야 하고, `hints_and_help_stay_in_sync` 테스트가 어긋남을 잡는다.

## 매니저 모드

| 동작 | 키 |
|---|---|
| 열기(정지 상태면 시작 후 포커스) | `Enter`, 클릭 |
| 이동 | `j`/`k`, `↑`/`↓`, `1`–`9`, `Home`/`End` |
| 필터 | `/` (`Enter` 유지, `Esc` 해제. 매니저에서도 `Esc`가 유지 중인 필터를 해제) |
| 추가 | `a` |
| 한 줄 전송 | `m` |
| 중지 | `s` (확인창) |
| 재시작 | `r` |
| 삭제 | `d` 또는 `Delete` (확인창. 실행 중이면 먼저 종료. 파일은 건드리지 않음) |
| 전체 시작 | `S` |
| 스크롤 | `PgUp`/`PgDn`, 마우스 휠 |
| 도움말 | `?` |
| 종료 | `q`, `Ctrl+C` (세션이 있으면 확인창) |

## 터미널(포커스) 모드

- `Alt+1`–`Alt+9`: 포커스를 유지한 채 해당 번호 프로젝트로 전환(매니저의 `1`–`9`와 같은 번호). 멈춘 프로젝트면 매니저로 간다. 이 조합은 세션에 전달되지 않는다.
- `Ctrl+Q`: 매니저로 복귀. 위의 `Alt+숫자`와 함께 squad가 가져가는 키다. 사이드바를 클릭하거나 마우스 가운데 버튼을 눌러도 복귀한다(가운데 버튼은 v0.7.0, 이 PC에서 직접 눌러 확인하지 못함).
- 그 밖의 모든 키는 세션으로 전달된다. `Esc`와 `Ctrl+G`도 포함(Claude Code는 `Esc`를 중단과 되감기에, `Ctrl+G`를 에디터 열기에 쓴다).
- 스크롤은 `Shift+PgUp`/`Shift+PgDn`, 라이브로 복귀는 `Shift+End` 또는 입력.
- 마우스: 사이드바 행 클릭은 선택, 실행 중인 터미널 영역 클릭은 포커스.

## 바뀐 이력

| 동작 | 이전 | 현재 |
|---|---|---|
| 필터 | `f` | `/` |
| 한 줄 전송 | `/` | `m` |
| 중지 | `x` (v0.5.0까지 `Delete`도) | `s` |
| 전체 시작 | `s` | `S` |
| 삭제 | `Delete` | `d`, `Delete` |
| 이동 | `n`/`p` | `j`/`k` |

이전 키 `x`, `n`, `p`는 손에 익은 동작이라 계속 동작하지만 도움말과 힌트에는 나오지 않는다.

## 결정과 주의

- **포커스 이탈 키:** 예전에는 `Esc`가 포커스를 풀어서 에이전트에 `Esc`를 보내려면 `Ctrl+G` 접두사를 거쳐야 했고, `Ctrl+G` 자체도 에이전트가 쓰는 키였다. `Esc`와 `Ctrl+G`를 세션에 그대로 넘기고 이탈 키를 `Ctrl+Q` 하나로 줄였다. `Ctrl+Q`를 고른 이유: 알려진 에이전트 단축키와 겹치는 것을 찾지 못했고, Ctrl+A~Z 범위라 crossterm이 문자 키로 보고할 것으로 판단했다(둘 다 이 PC에서 직접 눌러 확인하지는 못했다). `Ctrl+]`(텔넷 관례)는 Windows 콘솔에서 어떻게 보고되는지 몰라 쓰지 않았다. 바꾸려면 `focus_exit_key` 한 곳만 고치면 된다. 아직 배포 전(다음 릴리스 예정).
- 접두사 모드(`prefix`)는 코드에서 제거했다.

- `Delete`는 v0.5.0까지 중지 키였다가 삭제로 바뀌었다. 습관적으로 `Delete`로 중지하면 프로젝트가 사라지므로 중지는 `s`를 쓴다(삭제는 확인창 후 `y`).
- `S`(전체 시작)는 대문자라 Caps Lock이 켜져 있으면 `s`(중지) 자리에서 전체 시작이 실행된다. 되돌릴 수 없는 동작은 아니다.
- 입력, 필터, 추가 폼의 한 줄 편집은 `←` `→` `Home` `End` `Delete`를 지원한다.
